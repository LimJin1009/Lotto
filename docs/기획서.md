# 로또 번호 생성기 웹앱 기획서 — 로또 찐 번호

## 핵심 방향

사람들은 로또 번호 생성기를 "당첨 확률을 올리려고" 쓰지 않는다. **"이 번호에는 내 이야기가 있다"는 의미와 재미**를 얻으려고 쓴다.

- 생성 방식은 **이야기가 있는 방식**(꿈, 생일, 운세)과 **보는 재미가 있는 방식**(추첨기 영상)을 중심에 둔다.
- 다시 찾아오게 만드는 장치는 **당첨 확인과 당첨 인증 후기**다.
- 만든 번호마다 **"이 숫자가 왜 나왔는지" 이유를 함께 보여준다.** (예: "34 — 차량번호 가운데 두 자리")

## 1. 번호 생성 방식

| # | 방식 | 사용자 입력 | 번호 만드는 원리 | 단계 |
|---|---|---|---|---|
| 1 | 꿈 해몽 번호 | 꿈 종류 선택 → 세부 상황 선택 | 꿈마다 해몽 풀이와 관련 숫자 2~3개 + 나머지 무작위 | 1차 |
| 2 | 나만의 숫자 번호 | 생일, 전화번호, 차량번호, 기념일, 아무 숫자 | 숫자를 쪼개고 더해 1~45 범위로 바꿈 | 1차 |
| 3 | 통계 분석 번호 | 전략 선택: 많이 나온 번호 / 오래 안 나온 번호 / 균형 조합 | 1회부터 최신 회차까지 당첨 기록 계산 | 1차 |
| 4 | 추첨기 | "추첨 시작" 버튼 | 번호를 먼저 무작위로 정한 뒤, 그 번호가 나오도록 추첨 애니메이션을 그림 | 1차(2D) → 2차(3D·영상 저장) |
| 5 | 오늘의 운세 번호 | 생년월일, 띠, 별자리 | 날짜마다 바뀌는 운세 문구 + 행운 숫자 | 2차 |
| 6 | 고정수·제외수 필터 | 꼭 넣을 번호(5개까지), 뺄 번호(30개까지) | 다른 방식과 함께 쓰는 옵션. 고정수를 먼저 넣고, 제외수를 뺀 자리는 무작위로 채움. 연속번호 금지는 아직 | **1차 (고정수·제외수)** |
| 7 | 이름·소원 번호 | 이름, 소원 문장 | 글자마다 숫자로 바꾼 고정값 (같은 문장 → 같은 번호, 띄어쓰기 무시). 모자라면 문장으로 정해지는 난수로 채움 | 1차 |
| 8 | 가족·친구 궁합 번호 | 두 사람의 생일 | 두 날짜를 섞어 만듦 + 카톡 공유 | 2차 |

### 추첨기 원칙
- AI로 미리 만든 영상은 숫자를 그때그때 바꿀 수 없다. **번호는 먼저 정하고, 그 번호가 나오도록 브라우저에서 애니메이션을 그린다.**
- **모든 방식(꿈·나만의 숫자·통계·자동 추첨)이 추첨기를 거친다.** 버튼을 누르면 결과가 바로 뜨지 않고, 공기식 추첨기에서 공이 날아다니다가 정해진 번호가 하나씩 출구로 빨려 나온다.
- 공기식 추첨기: 바닥 노즐에서 바람이 위로 불어 공이 가운데로 솟구치고 벽을 타고 떨어지며 섞인다. 추첨 중 "바로 뽑기"를 누르면 남은 공과 남은 게임이 한 번에 나온다.
- 게임 수: 방식 고르는 카드 안 "몇 게임 뽑을까요?" 1~5게임 체크 칸(복권 한 장 = 5게임)에서 고른다. 처음 화면에 바로 보이도록 추첨기 위에 둔다. 고른 수만큼 게임을 이어서 뽑고, 고른 수는 기기에 기억한다. 이름·소원은 2게임부터 문장+게임 순서로 글자를 섞어 3개만 쓰고 나머지를 채운다 (같은 문장·같은 순서면 같은 번호).
- 2차에서 three.js 3D 추첨기, 테마(황금 돼지·용·크리스마스), 세로 영상(쇼츠 크기) 저장을 붙인다.

## 2. 당첨 인증 후기 (1차)

가짜 후기가 없어야 한다. **복권 QR로 확인한 당첨만** 올릴 수 있다.

- **누가 올리나:** 3개 이상 맞은 5등부터 1등까지. 꽝(2개 이하)은 못 올린다.
- **직접 입력은 못 올린다.** 누구나 당첨번호를 쳐 넣을 수 있어서다. "당첨 확인" 화면에서 QR(카메라·사진)로 확인한 복권만 "후기 남기기"가 나온다.
- **등수는 서버가 판정한다.** 앱이 보낸 QR 글자를 서버가 다시 풀어서 서버의 당첨번호와 맞춰 본다. 앱을 조작해도 꽝을 당첨으로 올릴 수 없다.
- **같은 복권의 같은 게임은 한 번만.** QR 글자+게임으로 만든 지문(해시)으로 막는다.
- **올리는 내용:** 닉네임(1~12자), 후기(5~300자), 회차·게임·자동/수동, 번호, 등수. 그 번호가 찐번호 번호함에 저장된 번호면 "꿈 해몽(으)로 뽑은 번호 · 돼지꿈"처럼 뽑은 방식도 함께 (사용자 기기 기록 기준).
- **후기 화면:** 인증된 당첨 수(등수별), 전체 / 1~3등 / 4등 / 5등 탭, 맞은 번호 표시, "QR 인증" 표시, 20개씩 더 보기.
- **사진은 1차에서 받지 않는다.** 복권 사진에는 바코드·일련번호가 있어 도용 위험이 있다. (나중에 올린다면 가림 처리 필수)
- **운영:** 문제 있는 후기는 `wrangler d1 execute` 명령으로 숨긴다 (`docs/후기서버.md`).

> 초기에 후기를 지어내서 채우지 않는다.

### 서버 (Cloudflare)
- Cloudflare Workers(무료)에서 작은 후기 서버(`worker/`)를 돌리고, 데이터는 Cloudflare D1(SQLite)에 둔다. 가게 컴퓨터(맥미니)와 완전히 떨어져 있다. 자세한 구성·관리는 `docs/후기서버.md`.
- 당첨번호는 서버가 공개 데이터에서 직접 받아 저장한다 (비밀 키 없음).
- 데이터는 D1 `lotto-reviews`. D1 이 지난 기간으로 되돌리기(Time Travel)를 해 주고, 필요하면 `wrangler d1 export` 로 파일 백업. 문제 있는 후기는 `hidden` 을 켜서 내린다.
- 앱 설정 `src/lib/config.ts` 의 `REVIEWS_API` 가 비어 있으면 후기 화면이 "준비 중"으로 보이고 후기 쓰기 칸이 나오지 않는다.
- 무료 한도(하루 요청 10만 번)를 넘으면 그날 후기만 멈춘다. 번호 뽑기·QR 확인은 그대로.

## 3. 다시 찾아오게 만드는 장치

| 기능 | 설명 | 단계 |
|---|---|---|
| 내 번호 당첨 확인 | 저장한 번호를 해당 회차 당첨번호와 자동으로 맞춤. 당첨된 번호에는 "QR로 확인하고 당첨 후기 남기기" 안내 | 1차(앱 열 때 확인) |
| 당첨 알림 | 알림을 켜면 추첨 전 회차에 저장한 번호를 서버에 맡겨 둠. 토요일 21시~·일요일 9시~ 10분마다 서버가 맞춰 보고 5등 이상이면 휴대폰 알림 → 누르면 당첨 확인(QR) 화면. 알림 문구는 "이 번호로 복권을 샀다면 QR로 확인하고 후기를 남겨 주세요" (저장한 번호는 산 복권이 아니므로 후기는 여전히 QR 인증만). 꽝은 알림 없음. 보낸 회차 번호는 지움. 아이폰은 홈 화면에 추가한 앱에서만 | 1차로 앞당김 (11/3) |
| 구매 알림 | 당첨 알림을 켠 사람이 "구매 알림도 받기"를 따로 켜면(처음엔 꺼짐), 토요일 18시에 "오늘 저녁 8시에 로또 판매가 끝나요"를 한 번 알림 → 누르면 번호 추첨 화면 |
| 번호함 전체 삭제 | 내 번호함 성적표 아래 "🗑️ 전체 삭제". 몇 게임을 지우는지와 되돌릴 수 없다는 것을 한 번 묻고 모두 지움 |
| 내 번호 성적표 | 내 번호함 위쪽. 저장한 번호 수, 추첨이 끝난 수, 5등 이상 횟수(등수별), 최고 기록(맞은 개수). 번호함 기록일 뿐 실제로 산 복권과 다를 수 있다고 적음 |
| 대박번호 받기 | 역대 1등 번호 중 6개 가운데 5개가 똑같았던 회차 쌍(1248회까지 21쌍, 앱이 당첨번호에서 직접 계산)에 나온 번호만 섞어서 뽑음. 그 회차들에 많이 나온 번호일수록 잘 나옴. 한 번에 늘 10게임, 고정수·제외수와 게임 수 고르기는 안 씀. "개발자 응원하기"(카카오페이 링크)를 누르면 그 기기에서 열림 — 실제로 보냈는지는 확인하지 않음. 10게임을 한 번 받으면 다시 잠기고, 또 응원하기를 눌러야 열림. 재미로 보는 번호이고 당첨 확률은 같다고 화면에 적음 |
| 흔들어서 뽑기 | 휴대폰을 세게 흔들면(1초 안에 세 번) 추첨 시작. 기울기와 같은 허용을 씀 (아이폰은 한 번 눌러 켜기). 추첨 중이거나 화면이 안 보일 때는 무시 |
| 당첨 확인 (QR 스캔) | 산 복권의 QR을 카메라로 찍거나 사진에서 찾거나 번호를 직접 넣으면 등수·당첨금을 바로 보여주고 번호함에 저장 | 1차 |
| 오늘의 운세 | 매일 바뀌어서 매일 들어올 이유가 됨 | 2차 |
| 공유 카드 | "돼지꿈 꾸고 받은 번호 🐷" 이미지 카드 | 1차(글 공유) → 2차(이미지·카톡) |
| 이번 주 인기 꿈 순위 | 가장 많이 고른 꿈 | 3차 (서버 필요) |

## 4. 화면 구성

```
홈(번호 추첨) ─ 다음 추첨까지 남은 시간
 │  ├ 방식 선택 (자동 추첨 / 꿈 해몽 / 나만의 숫자 / 이름·소원 / 통계) + 방식별 입력
 │  ├ 추첨기 (화면 가운데)
 │  ├ 뽑은 번호 (최대 5게임, 저장·공유). 1게임은 큰 카드, 2게임 이상은 복권 용지처럼 한 장에 A~E 한 줄씩 (줄을 누르면 이유, + 로 한 게임만 저장, 아래 "모두 저장"·공유)
 │  └ 최신 회차 당첨번호
 ├ 당첨 확인 (QR 찍기 / 사진으로 / 직접 입력 → 등수·당첨금·받는 곳)
 ├ 내 번호함 (저장 / 당첨 확인)
 ├ 당첨 후기 (QR 인증, 5등 이상, 등수 탭)
 └ 통계 (번호별 출현 횟수, 미출현 기간)
```

## 5. 개발 단계

| 단계 | 범위 |
|---|---|
| **1차 MVP** | 꿈 해몽, 나만의 숫자, 통계 분석, 2D 추첨기, 내 번호함(기기에 저장), 당첨 확인(QR 스캔), 휴대폰 설치(PWA), 최신 당첨번호, 통계 화면, 이름·소원 번호, 당첨 인증 후기 |
| **2차** | 3D 추첨기·영상 저장, 오늘의 운세, 연속번호 금지, 궁합 번호, 이미지 공유 카드, 카카오 로그인 |
| **3차** | 후기 사진(가림 처리), 유료 테마·광고 |

## 6. 기술

- 1차: Vite + React + TypeScript, 서버 없이 정적 사이트로 배포 가능
- 후기 서버: Cloudflare Workers + D1 (1차부터, 무료). 2차~: 회원, three.js(3D 추첨기)
- 당첨번호 데이터: 동행복권 옛 조회 주소(`common.do?method=getLottoNumber`)는 2026-11 현재 홈페이지로 넘어가서 쓸 수 없음. 대신 공개 데이터 [smok95/lotto](https://github.com/smok95/lotto)를 쓴다.
  - 앱 안에 `src/data/draws.json`(1회~최신)을 넣어 두고, 앱을 열 때 `latest.json`으로 새 회차가 있는지 확인한다.
  - `npm run update-draws`로 앱 안의 데이터를 새로 받는다.
  - 이 데이터는 오류가 있을 수 있으므로, 화면에 "정확한 당첨번호는 동행복권에서 확인" 문구를 둔다.
- 복권 QR 형식(공식 문서 없음, 실제 링크로 확인): `…qr.do?method=winQr&v=1248q243032353738…`
  - `v` = 회차 4자리 + 게임마다 [문자 1개 + 번호 6개 × 2자리]. 문자 q 자동, m 수동, s 반자동. 맨 뒤 일련번호는 쓰지 않는다.
  - QR 읽기: 브라우저 기본 기능(BarcodeDetector)이 있으면 쓰고, 없으면 ZXing(WebAssembly, 당첨 확인 화면에서만 받음). 카메라 영상과 사진은 기기 밖으로 보내지 않는다.
  - 카메라 화면(실시간 스캔)은 https 주소에서만 켜지고 사이트 카메라 권한이 필요하다. 안드로이드는 화면 위에 다른 앱이 떠 있으면(말풍선·화면 필터 등) 권한 요청 자체를 막는다.
  - 카메라 고르기: 휴대폰에 후면 카메라가 여러 개면 브라우저가 초점 고정 광각을 고를 수 있어서, 목록에서 메인 카메라(안드로이드 크롬은 보통 "camera2 0")로 다시 켠다. "카메라 바꾸기" 버튼으로 직접 바꿀 수 있고, 화면을 누르면 그 자리에 초점을 다시 맞춘다(지원 기기만).
  - 실시간 스캔: 자동 초점을 켜고 줌을 2배로 시작한다 (가까이 대면 초점이 안 맞아 흐려지므로 조금 떨어져서 찍게). 1·2·3배 줌 버튼, 플래시 버튼(지원 기기만). 휴대폰 기본 QR 인식(BarcodeDetector)으로 원본 화면을 먼저 읽고, 안 되면 ZXing(`zxing-wasm`)으로 네모 안을 원본 해상도로 읽는다. jsQR은 ZXing을 못 불러올 때만 쓴다 (흐린 로또 QR 시험에서 jsQR 0/6, ZXing 6/6). 스캔 화면 아래에 해상도·인식기·줌·초점 상태를 작게 표시한다 (원인 파악용).
  - QR은 읽었는데 로또 형식이 아니면 읽은 내용을 화면에 보여준다 (실제 복권 형식이 다를 때 고치기 위해).
