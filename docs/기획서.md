# 로또 번호 생성기 웹앱 기획서 — 로또 찐번호

## 핵심 방향

사람들은 로또 번호 생성기를 "당첨 확률을 올리려고" 쓰지 않는다. **"이 번호에는 내 이야기가 있다"는 의미와 재미**를 얻으려고 쓴다.

- 생성 방식은 **이야기가 있는 방식**(꿈, 생일, 운세)과 **보는 재미가 있는 방식**(추첨기 영상)을 중심에 둔다.
- 다시 찾아오게 만드는 장치는 **당첨 확인과 당첨 인증 후기**다.
- 만든 번호마다 **"이 숫자가 왜 나왔는지" 이유를 함께 보여준다.** (예: "34 — 차량번호 가운데 두 자리")

## 1. 번호 생성 방식

| # | 방식 | 사용자 입력 | 번호 만드는 원리 | 단계 |
|---|---|---|---|---|
| 1 | 꿈 해몽 번호 | 꿈 종류 선택 → 세부 상황 선택 | 꿈마다 해몽 풀이와 관련 숫자 2~3개 + 나머지 무작위 | 1차 |
| 2 | 나만의 숫자 번호 | 생일, 전화번호, 차량번호, 기념일, 아무 숫자 | 숫자를 쪼개고 더해 1~45 범위로 바꿈 | 1차 |
| 3 | 통계 분석 번호 | 전략 선택: 많이 나온 번호 / 오래 안 나온 번호 / 균형 조합 | 1회부터 최신 회차까지 당첨 기록 계산 | 1차 |
| 4 | 추첨기 | "추첨 시작" 버튼 | 번호를 먼저 무작위로 정한 뒤, 그 번호가 나오도록 추첨 애니메이션을 그림 | 1차(2D) → 2차(3D·영상 저장) |
| 5 | 오늘의 운세 번호 | 생년월일, 띠, 별자리 | 날짜마다 바뀌는 운세 문구 + 행운 숫자 | 2차 |
| 6 | 고정수·제외수 필터 | 꼭 넣을 숫자, 뺄 숫자, 연속번호 금지 | 다른 방식과 함께 쓰는 옵션 | 2차 |
| 7 | 이름·문장 번호 | 이름, 소원 문장 | 글자를 숫자로 바꾼 고정값 (같은 문장 → 같은 번호) | 2차 |
| 8 | 가족·친구 궁합 번호 | 두 사람의 생일 | 두 날짜를 섞어 만듦 + 카톡 공유 | 2차 |

### 추첨기 원칙
- AI로 미리 만든 영상은 숫자를 그때그때 바꿀 수 없다. **번호는 먼저 정하고, 그 번호가 나오도록 브라우저에서 애니메이션을 그린다.**
- **모든 방식(꿈·나만의 숫자·통계·자동 추첨)이 추첨기를 거친다.** 버튼을 누르면 결과가 바로 뜨지 않고, 공기식 추첨기에서 공이 날아다니다가 정해진 번호가 하나씩 출구로 빨려 나온다.
- 공기식 추첨기: 바닥 노즐에서 바람이 위로 불어 공이 가운데로 솟구치고 벽을 타고 떨어지며 섞인다. "빨리 감기"로 줄일 수 있다.
- 2차에서 three.js 3D 추첨기, 테마(황금 돼지·용·크리스마스), 세로 영상(쇼츠 크기) 저장을 붙인다.

## 2. 당첨 인증 후기 (3차)

가짜 후기가 없어야 한다. 실제 확인 절차를 거친 것만 "인증됨"을 붙인다.

1. 앱에서 만든 번호는 회차와 함께 **내 번호함에 자동 저장** (생성 시각 기록)
2. 추첨 뒤 저장 번호와 공식 당첨번호를 자동으로 맞춰봄 → 맞으면 "당첨 후보"
3. 사용자가 복권 사진을 올림 → 회차·번호가 저장 기록과 같으면 **"인증됨"**
4. 사진 속 바코드·일련번호는 올릴 때 자동으로 가림

후기 화면: 등수별 탭(1~5등), 어떤 방식으로 만든 번호인지 표시, 방식별 당첨 횟수 순위. 5등도 인증받아 후기가 쌓이게 한다.

> 초기에 후기를 지어내서 채우지 않는다. 처음에는 "이번 주 앱 사용자 번호 중 5등 이상 ○건"처럼 자동 집계한 실제 숫자를 보여준다.

## 3. 다시 찾아오게 만드는 장치

| 기능 | 설명 | 단계 |
|---|---|---|
| 내 번호 당첨 확인 | 저장한 번호를 해당 회차 당첨번호와 자동으로 맞춤 | 1차(앱 열 때 확인) → 3차(알림) |
| 당첨 확인 (QR 스캔) | 산 복권의 QR을 카메라로 찍거나 사진에서 찾거나 번호를 직접 넣으면 등수·당첨금을 바로 보여주고 번호함에 저장 | 1차 |
| 오늘의 운세 | 매일 바뀌어서 매일 들어올 이유가 됨 | 2차 |
| 공유 카드 | "돼지꿈 꾸고 받은 번호 🐷" 이미지 카드 | 1차(글 공유) → 2차(이미지·카톡) |
| 이번 주 인기 꿈 순위 | 가장 많이 고른 꿈 | 3차 (서버 필요) |

## 4. 화면 구성

```
홈(번호 추첨) ─ 다음 추첨까지 남은 시간
 │  ├ 방식 선택 (꿈 해몽 / 나만의 숫자 / 통계 / 자동 추첨) + 방식별 입력
 │  ├ 추첨기 (화면 가운데)
 │  ├ 뽑은 번호 (최대 5게임, 저장·공유)
 │  └ 최신 회차 당첨번호
 ├ 당첨 확인 (QR 찍기 / 사진으로 / 직접 입력 → 등수·당첨금·받는 곳)
 ├ 내 번호함 (저장 / 당첨 확인)
 ├ 당첨 후기 (3차)
 └ 통계 (번호별 출현 횟수, 미출현 기간)
```

## 5. 개발 단계

| 단계 | 범위 |
|---|---|
| **1차 MVP** | 꿈 해몽, 나만의 숫자, 통계 분석, 2D 추첨기, 내 번호함(기기에 저장), 당첨 확인(QR 스캔), 휴대폰 설치(PWA), 최신 당첨번호, 통계 화면 |
| **2차** | 3D 추첨기·영상 저장, 오늘의 운세, 고정수·제외수, 이름·궁합 번호, 이미지 공유 카드, 카카오 로그인 |
| **3차** | 당첨 인증 후기, 추첨 결과 알림, 유료 테마·광고 |

## 6. 기술

- 1차: Vite + React + TypeScript, 서버 없이 정적 사이트로 배포 가능
- 2차~: Supabase(회원·후기·사진 저장), three.js(3D 추첨기)
- 당첨번호 데이터: 동행복권 옛 조회 주소(`common.do?method=getLottoNumber`)는 2026-11 현재 홈페이지로 넘어가서 쓸 수 없음. 대신 공개 데이터 [smok95/lotto](https://github.com/smok95/lotto)를 쓴다.
  - 앱 안에 `src/data/draws.json`(1회~최신)을 넣어 두고, 앱을 열 때 `latest.json`으로 새 회차가 있는지 확인한다.
  - `npm run update-draws`로 앱 안의 데이터를 새로 받는다.
  - 이 데이터는 오류가 있을 수 있으므로, 화면에 "정확한 당첨번호는 동행복권에서 확인" 문구를 둔다.
- 복권 QR 형식(공식 문서 없음, 실제 링크로 확인): `…qr.do?method=winQr&v=1248q243032353738…`
  - `v` = 회차 4자리 + 게임마다 [문자 1개 + 번호 6개 × 2자리]. 문자 q 자동, m 수동, s 반자동. 맨 뒤 일련번호는 쓰지 않는다.
  - QR 읽기: 브라우저 기본 기능(BarcodeDetector)이 있으면 쓰고, 없으면 ZXing(WebAssembly, 당첨 확인 화면에서만 받음). 카메라 영상과 사진은 기기 밖으로 보내지 않는다.
  - 카메라 화면(실시간 스캔)은 https 주소에서만 켜지고 사이트 카메라 권한이 필요하다. 안드로이드는 화면 위에 다른 앱이 떠 있으면(말풍선·화면 필터 등) 권한 요청 자체를 막는다.
  - 카메라 고르기: 휴대폰에 후면 카메라가 여러 개면 브라우저가 초점 고정 광각을 고를 수 있어서, 목록에서 메인 카메라(안드로이드 크롬은 보통 "camera2 0")로 다시 켠다. "카메라 바꾸기" 버튼으로 직접 바꿀 수 있고, 화면을 누르면 그 자리에 초점을 다시 맞춘다(지원 기기만).
  - 실시간 스캔: 자동 초점을 켜고 줌을 2배로 시작한다 (가까이 대면 초점이 안 맞아 흐려지므로 조금 떨어져서 찍게). 1·2·3배 줌 버튼, 플래시 버튼(지원 기기만). 휴대폰 기본 QR 인식(BarcodeDetector)으로 원본 화면을 먼저 읽고, 안 되면 ZXing(`zxing-wasm`)으로 네모 안을 원본 해상도로 읽는다. jsQR은 ZXing을 못 불러올 때만 쓴다 (흐린 로또 QR 시험에서 jsQR 0/6, ZXing 6/6). 스캔 화면 아래에 해상도·인식기·줌·초점 상태를 작게 표시한다 (원인 파악용).
  - QR은 읽었는데 로또 형식이 아니면 읽은 내용을 화면에 보여준다 (실제 복권 형식이 다를 때 고치기 위해).
  - 그래서 "사진으로" 탭에 권한이 필요 없는 "카메라로 찍기"(휴대폰 기본 카메라 앱으로 찍기)와 "앨범에서 고르기"를 둔다. 실시간 스캔이 실패하면 이쪽으로 안내한다.
  - 당첨금은 smok95/lotto의 회차별 결과에서 가져온다 (1게임 기준, 세금 떼기 전). 화면에 "동행복권에서 다시 확인" 문구를 둔다.
- 휴대폰 설치(PWA): 앱 마켓 없이 홈 화면에 추가. `public/manifest.webmanifest`, 아이콘(`assets/icon.svg` → `npm run icons`로 PNG 생성), 서비스 워커(`public/sw.js`, 한 번 연 화면은 인터넷 없이도 열림).
  - 상단 "앱 설치" 버튼: 안드로이드 크롬은 바로 설치 창, 아이폰은 Safari "홈 화면에 추가" 안내, 카카오톡·인스타 등 앱 안 브라우저는 "다른 브라우저로 열기" 안내.
- 링크 미리보기(OG 태그): `index.html`에 제목·설명·이미지(`public/og-image.png`, 1200×630, `assets/og-image.svg` → `npm run icons`). 이미지 주소는 전체 주소로 적는다. 카카오톡은 미리보기를 오래 저장해 두므로, 바꾼 뒤에는 카카오 개발자 사이트의 "공유 디버거"에서 캐시를 지운다.
- 검색 노출(SEO): `seo/pages.ts` + `vite.config.ts`의 `seoPages` 플러그인이 빌드할 때 만든다.
  - 앱 화면은 자바스크립트로 그려져 검색 로봇(특히 네이버)이 잘 못 읽으므로, 글이 그대로 들어간 정적 페이지를 따로 만든다.
  - `/dream/`(꿈 해몽 모음), `/dream/{id}/`(꿈 38개 각각: 해몽, 상징 숫자, 상황별 숫자, 자주 묻는 질문, 같은 갈래 꿈 링크), `sitemap.xml`.
  - 첫 화면 `#root` 안에 소개 글과 인기 꿈 링크를 넣는다 (앱이 뜨면 앱 화면으로 바뀜). 대표 주소(canonical), 구조화 정보(WebApplication, 꿈 페이지는 BreadcrumbList·FAQPage·Article).
  - 꿈 페이지의 "추첨기로 뽑기"는 `#/?dream={id}`로 그 꿈이 골라진 채 앱을 연다.
  - 꿈 페이지 문구도 "확률이 올라간다"는 표현 금지. 숫자는 재미용 해석이라고 밝힌다.
  - `robots.txt`는 도메인 맨 위(`limjin1009.github.io/robots.txt`)에만 효력이 있어 넣지 않는다. 사이트 지도는 구글 서치 콘솔·네이버 서치어드바이저에 직접 제출한다.
- 배포: GitHub Pages (https://limjin1009.github.io/Lotto/). main에 올리면 자동 배포되고, 매주 일요일 10:00(한국 시간)에 최신 당첨번호를 받아 다시 배포한다 (`.github/workflows/deploy.yml`).

## 7. 꼭 지킬 것

- **"당첨 확률이 올라간다"는 표현을 쓰지 않는다.** 모든 조합의 확률은 같다(1등 1/8,145,060). 모든 화면에 "재미로 보는 번호" 문구를 둔다.
- **로또를 앱에서 팔거나 대신 사주는 기능은 넣지 않는다** (동행복권만 판매 가능).
- "1등 번호 유료 제공" 같은 기능은 넣지 않는다. 돈을 받는다면 테마나 광고 제거만 유료로 한다.
- 꿈 해몽 숫자는 이 앱이 정한 재미용 해석이다. 화면에 그렇게 밝힌다.
